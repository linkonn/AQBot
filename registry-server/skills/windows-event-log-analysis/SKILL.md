# Windows 日志分析

## 关键事件 ID

| ID | 含义 | 取证价值 |
|---|---|---|
| 4624 | 登录成功 | 关注 LogonType 3（网络）、10（远程桌面） |
| 4625 | 登录失败 | 短时间大量失败即暴力破解 |
| 4672 | 授予特殊权限 | 与 4624 配对看提权 |
| 4688 | 进程创建 | 命令行是核心证据（需开启审核） |
| 7045 | 服务安装 | 常见持久化 |
| 4698 | 计划任务创建 | 常见持久化 |
| 4720 / 4728 | 账户创建 / 加组 | 后门账户 |

## 步骤

1. 用 `EvtxECmd` 或 `chainsaw` 批量解析，统一输出 CSV / JSON。
2. 先建时间线：按 `TimeCreated` 排序，标注主机、账户、来源 IP。
3. 找入口：4625 密集段 → 首个 4624（Type 3/10）→ 紧随的 4672。
4. 找落地：4688 中异常命令行（`powershell -enc`、`certutil -urlcache`、`bitsadmin`）。
5. 找持久化：7045 的服务路径是否指向 `%TEMP%`、`ProgramData` 等非常规目录。
6. 找横向：同一账户在短时间内登录多台主机。
7. 与文件系统时间（$MFT）、注册表（Amcache/UserAssist）交叉验证。

## 判读注意

- 4624 的 `SubjectUserName` 是登录发起方，`TargetUserName` 才是被登录账户，别混。
- 系统时间被改过时，优先用日志内的 `SystemTime` 与文件时间差反推。
- 清日志会留下 1102 事件，清之前的事件仍在其他主机的转发日志里。

## 输出

给出「入口 → 提权 → 持久化 → 横向 → 外传」五段时间线，每段标注证据事件 ID 与记录号。
